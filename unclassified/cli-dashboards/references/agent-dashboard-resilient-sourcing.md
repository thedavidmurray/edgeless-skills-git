# Reference: Resilient Data Sourcing for Agent Infrastructure Dashboards

Date: 2026-06-03
Context: Edgeless OS — unified terminal dashboard for swarm state, Paperclip backlog, cron health, vault metrics, and system health.
File: `scripts/edgeless-os-dashboard.py`

## Problem

Agent dashboards that consume live infrastructure APIs (Paperclip, Hermes cron, ChromaDB) frequently hit one of three failure modes:
1. **API latency** — Paperclip `/api/companies/{cid}/issues` returns empty body or times out after 20s
2. **CLI parsing fragility** — `hermes cron list` output format changes or wraps, breaking regex-based parsers
3. **Service flapping** — ChromaDB / Paperclip / cron runner appear "up" in memory but fail health probes

## Solutions

### 1. Hermes cron state — read jobs.json directly

**Do NOT parse `hermes cron list` output.** Read `~/.hermes/cron/jobs.json` directly.

```python
import json, pathlib

jobs = json.loads(pathlib.Path("~/.hermes/cron/jobs.json").expanduser().read_text())
active = sum(1 for j in jobs["jobs"] if j.get("enabled") and not j.get("paused_at"))
paused = sum(1 for j in jobs["jobs"] if j.get("paused_at"))
errors = sum(1 for j in jobs["jobs"] if j.get("last_status") == "error")
```

The JSON structure is authoritative: `{"jobs": [...], "updated_at": "..."}` where each job has `enabled`, `paused_at`, `last_status`, `schedule`, `paused_reason`.

### 2. Paperclip backlog — API fallback to cached markdown

When `GET /api/companies/{cid}/issues?limit=200` is slow or empty, parse the daily fleet report instead.

```python
import re, pathlib, glob

# Find the most recent fleet-daily report
reports = sorted(glob.glob("claude-vault/13-Reports/daily-alignment/*-fleet-daily.md"))
latest = pathlib.Path(reports[-1]).read_text()

# Extract counts with regex
alive = int(re.search(r"(\d+)\s+active\s+issues", latest).group(1))
blocked = int(re.search(r"(\d+)\s+blocked", latest).group(1))
```

This report is generated by the `fleet-daily` cron (uses `paperclip-fleet-analyzer` skill). It already contains the exact counts the dashboard needs. Label the rendered table with `Source: fleet-daily` to indicate the fallback.

### 3. Service health — curl probes, not tool inference

Never infer service health from "tool availability" or "last session memory". Probe directly.

```python
import subprocess

def probe(url: str, timeout: int = 2) -> bool:
    result = subprocess.run(
        ["curl", "-s", "--max-time", str(timeout), url],
        capture_output=True, text=True
    )
    return result.returncode == 0 and len(result.stdout) > 0

paperclip_up = probe("http://localhost:3100/api/health")
chromadb_up = probe("http://localhost:8100/api/v1/heartbeat")
```

For Paperclip, a valid response includes agent JSON even if the health endpoint is unimplemented — any non-empty 200-level response proves the server is alive.

### 4. Vault metrics — find + du for large trees

Counting markdown files and total size in a 4.9 GB, 23K+ file vault:

```python
import subprocess

def vault_metrics(path: str = "claude-vault") -> dict:
    files = subprocess.run(
        ["find", path, "-name", "*.md"], capture_output=True, text=True
    )
    file_count = len(files.stdout.strip().split("\n")) if files.stdout else 0

    size = subprocess.run(
        ["du", "-sm", path], capture_output=True, text=True
    )
    size_mb = float(size.stdout.split()[0]) if size.stdout else 0

    return {"file_count": file_count, "size_mb": size_mb}
```

## Graceful Degradation Rules

1. **Always show something.** If the API is down, show cached data with a timestamp. If the cache is missing, show "N/A" rather than crashing the dashboard.
2. **Label the data source.** When using cached or fallback data, append `(Source: fleet-daily)` or `(cached)` to the table caption so the user knows the freshness.
3. **Fail fast on probes.** Use `--max-time 2` for curl, not 30s. The dashboard should render in < 3 seconds even if half the services are down.
4. **Separate render from fetch.** Fetch all data into a plain dict first, then render. Never mix I/O and rich.Table construction — it makes partial failures impossible to recover from.

## Anti-patterns

- **Parsing CLI output with regex.** `hermes cron list` output changes between versions. JSON is the contract.
- **Assuming localhost services are up because the tool exists.** The tool can be installed while the service is down. Always probe.
- **Blocking the render on a slow API.** If Paperclip takes 20s, the dashboard hangs. Fetch with short timeouts, or skip and use cache.
- **Using `web_extract` or `browser` for localhost.** These tools cannot access localhost. Use `curl` via `subprocess` or `execute_code` with `requests`.
